## Decisions Made

- **testseed added to dev segments.** Task 1 was advertised as "behaviour-preserving" in the plan, but the rename from `internal/test/` to `internal/testseed/` broke the pre-existing INFO downgrade on constants.go because `test` is a dedicatedDevSegment and `testseed` is not. Added `testseed` to both `devPathSegments` and `dedicatedDevSegments` in the same refactor commit. Semantically correct: `testseed` means "test seed data", definitely a dev-only fixture marker.
- **stripe_client.go expected severity INFO, not CRITICAL.** The plan pre-validation step called for running panscanner directly against the file and capturing the emitted line; that run correctly returned line=5. The plan then assumed the severity would be CRITICAL. The fixture test runs with `includeTaint=true`, which activates `panscanner/taint_bridge.go` and downgrades transit-only struct fields to INFO per PCI SSC FAQ. This is correct behaviour — the struct is a plain DTO with no DB store, no log, no network sink — so the taint engine proves it is non-persistent memory. Encoded the contract row as PAN-KEYWORD INFO; the D-03 guard still holds because even an INFO finding requires the walker to have entered `internal/integration/`.
- **PAN-TYPE row removed.** Same reason: the taint engine suppresses PAN-TYPE on transit-only struct fields.
- **gitwalker tests symlink resolution.** On macOS `t.TempDir()` returns `/var/folders/...` but `scanner.GitTrackedFiles` internally runs `filepath.EvalSymlinks` and returns paths under `/private/var/folders/...`. Naive `filepath.Rel(tmpdir, absPath)` returns `../../../private/var/folders/...`. Tests now resolve the tmpdir first so assertions work uniformly.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] testseed rename broke pre-existing dev-context downgrade**
- **Found during:** Task 1 verification (make test-fixture after rename)
- **Issue:** Plan claimed "Behaviour-preserving: make test-fixture still passes" but the fixture failed with `severity critical: want 41 got 42` and a missing INFO finding on `internal/testseed/constants.go`. Root cause: `scanner/devcontext.go` treats `test` as a dedicatedDevSegment; after the rename, `testseed` no longer matched and the cryptoscanner emitted CRITICAL instead of the expected INFO.
- **Fix:** Added `testseed` to `devPathSegments` and `dedicatedDevSegments` in scanner/devcontext.go.
- **Files modified:** scanner/devcontext.go
- **Committed in:** c7dd0ad (Task 1 refactor commit)

**2. [Rule 1 - Bug] stripe_client.go expected CRITICAL but taint engine downgrades to INFO**
- **Found during:** Task 3 GREEN verification (make test-fixture after walker integration)
- **Issue:** Plan pre-validated line=5 correctly but did not account for `includeTaint=true` in the fixture test. Taint engine classifies the plain StripeChargeRequest struct as transit-only (no persistence sink) and downgrades PAN-KEYWORD to INFO and drops PAN-TYPE entirely — semantically correct per PCI SSC FAQ.
- **Fix:** Updated EXPECTED-FINDINGS.md row to PAN-KEYWORD INFO; removed PAN-TYPE row; recalibrated counters: critical 42→41, medium 26→25, info 35→36, expected_active 151→150, expected_total_findings 185→184.
- **Files modified:** testdata/vulnerable-payment-service/EXPECTED-FINDINGS.md
- **Committed in:** bb83f0c (Task 3 GREEN commit)

**3. [Rule 1 - Bug] gitwalker tests missed symlink resolution on macOS**
- **Found during:** Task 3 GREEN verification (targeted unit tests)
- **Issue:** `filepath.Rel(tmpdir, absPath)` returned `../../../private/var/folders/...` because GitTrackedFiles evaluates symlinks internally. Test assertions on `internal/integration/stripe.go` etc. never matched.
- **Fix:** Both gitwalker tests now call `filepath.EvalSymlinks(dir)` before the Rel computation.
- **Files modified:** scanner/gitwalker_test.go
- **Committed in:** bb83f0c (Task 3 GREEN commit)

**Total deviations:** 3 auto-fixes (all Rule 1 bugs — plan assumption mismatches with actual scanner behaviour)
